# IO Messenger 

 **[Живое демо на Vercel](https://io-nu-ruddy.vercel.app/)**
>  **Важное примечание для тестирования:** Бэкенд развернут на бесплатном тарифе Render. Если приложением долго не пользовались, сервер уходит в «спящий режим». Первая загрузка или авторизация может занять **до 30–50 секунд**, пока сервер просыпается. В будущем проекте ECHO эта проблема будет решена переносом инфраструктуры.

**IO** — это амбициозный фулстэк-эксперимент по созданию веб-мессенджера в реальном времени. Проект вдохновлен спутником Ио (самым сейсмически активным телом Солнечной системы), что отражает динамичную, "кипящую" природу современных real-time приложений. 

Цель проекта — пройти полный цикл разработки крупного продукта в одиночку: от идеи до деплоя, столкнуться с реальными архитектурными вызовами и найти их решения.

>  **Note / Работа над ошибками:** Этот проект стал для меня огромной технологической песочницей. Столкнувшись с проблемами производительности и масштабирования на этапе реализации, я извлекла бесценный опыт, который сейчас перерождается в архитектурно чистый проект-преемник — **ECHO**.

##  Ключевой функционал

* **Real-time Messaging** — мгновенный обмен сообщениями без задержек.
* **Global State Management** — эффективное управление состоянием без лишних ререндеров.
* **Responsive UI** — адаптивный и кастомный интерфейс.

##  Стек технологий (Frontend)

* **Next.js (App Router)** — каркас приложения, SSR и оптимизация маршрутизации.
* **React & TypeScript** — строгая типизация (освоенная и внедренная в процессе разработки).
* **Socket.io-client** — постоянное двустороннее соединение с сервером для real-time фич.
* **Jotai** — атомарный стейт-менеджер, внедрив который, удалось победить проблему бесконечных ререндеров от React Context.

##  Архитектурная эволюция и преодоление трудностей

Этот проект пережил настоящий "производственный ад", который в итоге качественно прокачал мои навыки:

1. **От хаоса к FSD**: Изначально проект строился на простой модульной структуре, которая быстро завязалась в узел при росте фич. В процессе разработки вся кодовая база была полностью переписана на **Feature-Sliced Design (FSD)**. Это было больно, но теперь архитектура предсказуема и разделена на слои.
2. **Оптимизация рендеринга**: Попытка построить мессенджер на стандартных React Context привела к каскадным ререндерам при каждом новом сообщении. Проблема была решена миграцией на атомарное управление состоянием с помощью **Jotai**.
